# 通知接口错误修复总结

## 🐛 问题描述

运行时出现两个关键错误：

### 错误 1: Redis 序列化 LocalDateTime 失败
```
Could not write JSON: Java 8 date/time type `java.time.LocalDateTime` not supported by default
```

### 错误 2: Integer 无法转换为 Long
```
class java.lang.Integer cannot be cast to class java.lang.Long
```

---

## 🔍 问题分析

### 错误 1 根因
**问题**：`GenericJackson2JsonRedisSerializer` 默认使用的 ObjectMapper 没有注册 `JavaTimeModule`

**影响范围**：
- ✅ `/api/notifications/recent` - 获取最近通知
- ✅ `/api/notifications/unread` - 获取未读通知
- ✅ Redis 缓存序列化

**技术细节**：
- `CacheConfig` 中创建的 `GenericJackson2JsonRedisSerializer` 使用无参构造函数
- 无参构造函数会创建一个新的默认 ObjectMapper
- 这个 ObjectMapper 没有包含我们在 `JacksonConfig` 中配置的 `JavaTimeModule`

---

### 错误 2 根因
**问题**：JPA `count` 查询返回类型不确定，缓存反序列化时类型不匹配

**影响范围**：
- ✅ `/api/notifications/unread/count` - 获取未读数量

**技术细节**：
- JPA 的 `countBy...` 方法在不同数据库下可能返回 `Integer` 或 `Long`
- 从 Redis 反序列化时，JSON 数字默认解析为 `Integer`
- 方法声明返回 `Long`，导致类型转换异常

---

## ✅ 修复方案

### 修复 1: CacheConfig 使用自定义 ObjectMapper

**文件**: `CacheConfig.java`

**修改前**:
```java
@Bean
public CacheManager cacheManager(RedisConnectionFactory connectionFactory) {
    RedisCacheConfiguration defaultConfig = RedisCacheConfiguration.defaultCacheConfig()
            .serializeValuesWith(
                    RedisSerializationContext.SerializationPair.fromSerializer(
                            new GenericJackson2JsonRedisSerializer()  // ❌ 使用默认 ObjectMapper
                    )
            );
    // ...
}
```

**修改后**:
```java
@Bean
public CacheManager cacheManager(RedisConnectionFactory connectionFactory, ObjectMapper objectMapper) {
    // ✅ 使用自定义 ObjectMapper 创建序列化器
    GenericJackson2JsonRedisSerializer jsonSerializer = new GenericJackson2JsonRedisSerializer(objectMapper);
    
    RedisCacheConfiguration defaultConfig = RedisCacheConfiguration.defaultCacheConfig()
            .serializeValuesWith(
                    RedisSerializationContext.SerializationPair.fromSerializer(jsonSerializer)
            );
    // ...
}
```

**关键改动**:
1. `cacheManager` 方法注入 `ObjectMapper` 参数
2. 使用注入的 `ObjectMapper` 创建 `GenericJackson2JsonRedisSerializer`
3. 这个 ObjectMapper 包含了 `JavaTimeModule`，支持 `LocalDateTime` 序列化

---

### 修复 2: 明确 count 查询返回类型

**文件**: `NotificationRepository.java`

**修改前**:
```java
Long countByUserIdAndIsReadFalse(Long userId);
```

**修改后**:
```java
@Query("SELECT COUNT(n) FROM Notification n WHERE n.user.id = :userId AND n.isRead = false")
Long countByUserIdAndIsReadFalse(@Param("userId") Long userId);
```

**文件**: `NotificationService.java`

**修改前**:
```java
public Long getUnreadCount(String username) {
    User user = getUserByUsername(username);
    return notificationRepository.countByUserIdAndIsReadFalse(user.getId());
}
```

**修改后**:
```java
public Long getUnreadCount(String username) {
    User user = getUserByUsername(username);
    Long count = notificationRepository.countByUserIdAndIsReadFalse(user.getId());
    // 确保返回的是 Long 类型（防止缓存反序列化时类型不匹配）
    return count != null ? count : 0L;
}
```

**关键改动**:
1. 使用 `@Query` 明确指定 `COUNT(n)` 返回 `Long`
2. Service 层添加空值检查，确保返回 `Long` 类型

## 🎯 核心知识点

### 1. GenericJackson2JsonRedisSerializer 的构造函数

```java
// 无参构造 - 创建默认 ObjectMapper（不包含自定义配置）
new GenericJackson2JsonRedisSerializer()

// 有参构造 - 使用自定义 ObjectMapper（包含 JavaTimeModule）
new GenericJackson2JsonRedisSerializer(objectMapper)
```

---

### 2. JPA COUNT 查询类型问题

| 方法 | 可能返回类型 | 推荐做法 |
|------|-------------|---------|
| `countBy...` | `Integer` 或 `Long` | 使用 `@Query` 明确 |
| `@Query("SELECT COUNT(...)")` | 明确返回 `Long` | ✅ 推荐 |

---

### 3. Redis 序列化配置优先级

```
自定义 ObjectMapper (注入)
    ↓
GenericJackson2JsonRedisSerializer
    ↓
RedisCacheConfiguration
    ↓
Redis 存储
```

## 🔄 后续优化建议

### 1. 统一序列化配置

**建议**: 创建一个统一的 `ObjectMapper` Bean，供所有组件使用

```java
@Configuration
public class JacksonConfig {
    
    @Bean
    @Primary
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.registerModule(new JavaTimeModule());
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
        return mapper;
    }
}
```

---

### 2. 缓存监控

**建议**: 添加缓存命中率监控

```java
@Aspect
@Component
public class CacheMonitorAspect {
    
    @Around("@annotation(org.springframework.cache.annotation.Cacheable)")
    public Object monitorCache(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long duration = System.currentTimeMillis() - start;
        
        log.info("缓存操作耗时: {}ms", duration);
        return result;
    }
}
```

---

### 3. 类型安全的缓存 Key

**建议**: 使用枚举或常量类管理缓存键

```java
public enum CacheKey {
    USER_NOTIFICATIONS("userNotifications::%s"),
    NOTIFICATION_COUNT("notificationCount::%s");
    
    private final String pattern;
    
    CacheKey(String pattern) {
        this.pattern = pattern;
    }
    
    public String format(Object... args) {
        return String.format(pattern, args);
    }
}
```
