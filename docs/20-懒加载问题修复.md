# LazyInitializationException 修复说明

## 🐛 问题描述

**错误信息**：
```
org.hibernate.LazyInitializationException: Could not initialize proxy [com.example.cloudnotes.entity.Todo#3] - no session
```

**发生位置**：
`TodoReminderScheduler.sendReminder()` 第 68 行

---

## 🔍 根本原因

### 问题链条

1. **查询阶段**：`scanAndSendReminders()` 调用 `findPendingReminders()`
   ```java
   List<TodoReminder> pendingReminders = reminderRepository.findPendingReminders(now);
   ```

2. **懒加载**：查询只加载 `TodoReminder` 本身，关联的 `Todo` 是懒加载代理
   ```sql
   -- 原始查询（错误）
   SELECT r.* FROM todo_reminders r WHERE ...
   -- Todo 对象未加载，是一个代理
   ```

3. **Session 关闭**：查询完成后，Hibernate Session 关闭

4. **访问代理**：在 `sendReminder()` 方法中访问 `reminder.getTodo().getStatus()`
   ```java
   if (todo.getStatus() == Todo.TodoStatus.COMPLETED) { // ❌ 此时 Session 已关闭
   ```

5. **抛出异常**：代理无法初始化，因为 Session 已关闭

---

## ✅ 解决方案

### 方案：使用 JOIN FETCH 预加载关联对象

**修改前**：
```java
@Query("SELECT r FROM TodoReminder r " +
       "WHERE r.remindAt <= :now " +
       "AND r.isSent = false " +
       "AND r.isActive = true " +
       "ORDER BY r.remindAt ASC")
List<TodoReminder> findPendingReminders(@Param("now") LocalDateTime now);
```

**修改后**：
```java
@Query("SELECT r FROM TodoReminder r " +
       "JOIN FETCH r.todo t " +        // ✅ 预加载 Todo
       "JOIN FETCH t.user " +           // ✅ 预加载 User
       "WHERE r.remindAt <= :now " +
       "AND r.isSent = false " +
       "AND r.isActive = true " +
       "ORDER BY r.remindAt ASC")
List<TodoReminder> findPendingReminders(@Param("now") LocalDateTime now);
```

### 执行的 SQL

```sql
-- 一次性加载所有需要的数据
SELECT 
    r.*, 
    t.id, t.title, t.status, t.due_date, ...,
    u.id, u.username, u.email, ...
FROM todo_reminders r
INNER JOIN todos t ON r.todo_id = t.id
INNER JOIN users u ON t.user_id = u.id
WHERE r.remind_at <= ?
  AND r.is_sent = false
  AND r.is_active = true
ORDER BY r.remind_at ASC;
```

## 💡 最佳实践

### 1. 优先使用 JOIN FETCH

**适用场景**：
- 明确知道需要访问关联对象
- 关联对象数量可控（避免笛卡尔积）

**优点**：
- 一次查询加载所有数据
- 避免 N+1 查询问题
- 避免 LazyInitializationException

### 2. 其他解决方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| JOIN FETCH | 性能最优，一次查询 | 需要修改查询 | ⭐⭐⭐⭐⭐ |
| @Transactional | 代码改动小 | 事务时间长，锁持续时间长 | ⭐⭐ |
| EAGER 加载 | 无需修改查询 | 总是加载，即使不需要 | ⭐ |
| DTO 投影 | 精确控制字段 | 需要额外 DTO 类 | ⭐⭐⭐⭐ |

### 3. 何时使用各种方案

```java
// ✅ 推荐：确定需要关联对象时
@Query("SELECT r FROM TodoReminder r JOIN FETCH r.todo WHERE ...")

// ⚠️ 谨慎：可能导致性能问题
@ManyToOne(fetch = FetchType.EAGER)
private Todo todo;

// ✅ 备选：只需要部分字段时
@Query("SELECT new TodoReminderDTO(r.id, t.title, t.status) FROM TodoReminder r JOIN r.todo t WHERE ...")

// ❌ 不推荐：事务范围过大
@Transactional  // 放在 Service 层最外层
public void processReminders() {
    // 大量业务逻辑
}
```
