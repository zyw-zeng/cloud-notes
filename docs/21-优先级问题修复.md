# 优先级枚举修复说明

## 🐛 问题描述

**错误信息**：
```
JSON parse error: Cannot deserialize value of type 
`com.example.cloudnotes.entity.Todo$TodoPriority` from String "NORMAL": 
not one of the values accepted for Enum class: [HIGH, LOW, MEDIUM]
```

**问题原因**：
- 前端发送的优先级值：`LOW`, `NORMAL`, `HIGH`, `URGENT`
- 后端实际的枚举值：`LOW`, `MEDIUM`, `HIGH`
- 文档与代码不一致

## 📞 常见问题

### Q1: 为什么不保留 NORMAL？

**A**: 
- `NORMAL` 语义不够清晰，容易与 `MEDIUM` 混淆
- `MEDIUM` 更准确地表达"中等优先级"
- 与 LOW/MEDIUM/HIGH 形成更好的层级关系

---

### Q2: 如何处理旧的 URGENT 数据？

**A**: 
- 建议映射为 `HIGH`
- 如果业务需要，可以使用 `isImportant` 字段标记紧急任务
- 或使用标签系统添加"紧急"标签

---

### Q3: 前端已经使用了 NORMAL，如何快速修复？

**A**: 全局搜索替换
```bash
# 在前端项目中
grep -r "NORMAL" --include="*.ts" --include="*.tsx" --include="*.js" --include="*.vue"

# 替换
sed -i 's/"NORMAL"/"MEDIUM"/g' src/**/*.{ts,tsx,js,vue}
sed -i 's/NORMAL/MEDIUM/g' src/**/*.{ts,tsx,js,vue}
```
