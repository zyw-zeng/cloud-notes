# 日志系统使用指南

## 📋 日志系统概述

本项目使用 **SLF4J + Logback** 作为日志框架，提供了完整的日志记录和管理功能。

---

## 📁 日志文件结构

日志文件存储在项目根目录的 `logs/` 文件夹下：

```
logs/
├── cloud-notes.log              # 所有日志（INFO 及以上）
├── cloud-notes-error.log        # 错误日志（ERROR）
├── cloud-notes-business.log     # 业务日志（可选）
└── archive/                     # 历史日志归档
    ├── cloud-notes-2025-11-28.0.log
    ├── cloud-notes-2025-11-28.1.log
    └── cloud-notes-error-2025-11-28.0.log
```

### 日志文件特性
- ✅ **自动滚动**：每个文件最大 10MB，超过后自动创建新文件
- ✅ **按日期归档**：每天自动归档到 `archive/` 目录
- ✅ **自动清理**：保留最近 30 天的日志，总大小不超过 1GB
- ✅ **异步写入**：不影响应用性能

## 🎯 在代码中使用日志

### 1. 引入 Lombok 注解（推荐）

```java
import lombok.extern.slf4j.Slf4j;

@Slf4j
@Service
public class UserService {
    
    public void registerUser(String username) {
        log.info("开始注册用户: {}", username);
        
        try {
            // 业务逻辑
            log.debug("验证用户名是否重复");
            
            // 成功
            log.info("用户注册成功: {}", username);
        } catch (Exception e) {
            log.error("用户注册失败: {}", username, e);
            throw e;
        }
    }
}
```

### 2. 手动创建 Logger

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class NoteService {
    private static final Logger log = LoggerFactory.getLogger(NoteService.class);
    
    public void createNote(NoteDTO dto) {
        log.info("创建笔记: {}", dto.getTitle());
    }
}
```

## 📊 日志级别说明

| 级别    | 用途                           | 示例                           |
|---------|--------------------------------|--------------------------------|
| **TRACE** | 最详细的调试信息               | `log.trace("进入方法: {}", method)` |
| **DEBUG** | 调试信息                       | `log.debug("查询参数: {}", params)` |
| **INFO**  | 重要业务流程                   | `log.info("用户登录: {}", username)` |
| **WARN**  | 警告信息（不影响运行）         | `log.warn("配置缺失，使用默认值")` |
| **ERROR** | 错误信息（需要关注）           | `log.error("数据库连接失败", e)` |

## 🛠️ 常用日志模式

### 1. 记录方法执行

```java
@Slf4j
@Service
public class NotebookService {
    
    public Notebook createNotebook(NotebookDTO dto, String username) {
        log.info("创建笔记本 - 用户: {}, 笔记本名: {}", username, dto.getName());
        
        // 业务逻辑
        Notebook notebook = notebookRepository.save(newNotebook);
        
        log.info("笔记本创建成功 - ID: {}", notebook.getId());
        return notebook;
    }
}
```

### 2. 记录异常信息

```java
try {
    // 可能抛出异常的代码
    riskyOperation();
} catch (IOException e) {
    // 记录完整的异常堆栈
    log.error("文件操作失败: {}", filename, e);
    throw new RuntimeException("文件处理错误", e);
}
```

### 3. 条件日志（避免性能损耗）

```java
// ❌ 错误：每次都会拼接字符串
log.debug("用户数据: " + user.toString());

// ✅ 正确：只在 DEBUG 级别开启时才执行
if (log.isDebugEnabled()) {
    log.debug("用户数据: {}", expensiveOperation());
}

// ✅ 更好：使用占位符，框架会优化
log.debug("用户数据: {}", user);
```

### 4. 记录业务关键节点

```java
@Slf4j
@Service
public class PaymentService {
    
    public void processPayment(OrderDTO order) {
        log.info("【支付】开始处理订单: {}", order.getOrderId());
        
        // 1. 验证订单
        log.info("【支付】验证订单信息");
        validateOrder(order);
        
        // 2. 调用支付接口
        log.info("【支付】调用第三方支付 - 金额: {}", order.getAmount());
        PaymentResult result = callPaymentApi(order);
        
        // 3. 更新订单状态
        log.info("【支付】更新订单状态 - 结果: {}", result.getStatus());
        updateOrderStatus(order, result);
        
        log.info("【支付】订单处理完成: {}", order.getOrderId());
    }
}
```

## 📝 日志最佳实践

### ✅ 推荐做法

1. **使用 Lombok 的 @Slf4j 注解**
   ```java
   @Slf4j
   @Service
   public class MyService { }
   ```

2. **使用占位符，而不是字符串拼接**
   ```java
   // ✅ 推荐
   log.info("用户 {} 执行了操作 {}", username, action);
   
   // ❌ 不推荐
   log.info("用户 " + username + " 执行了操作 " + action);
   ```

3. **记录完整异常堆栈**
   ```java
   log.error("操作失败", e);  // 会打印完整堆栈
   ```

4. **敏感信息脱敏**
   ```java
   log.info("用户登录 - 用户名: {}, 密码: ******", username);
   ```

### ❌ 避免的做法

1. ❌ 不要使用 `System.out.println()`
2. ❌ 不要在循环中打印大量 DEBUG 日志
3. ❌ 不要记录敏感信息（密码、token、身份证等）
4. ❌ 不要在日志中记录超大对象

## 🔧 修改日志级别（无需重启）

如果使用了 Spring Boot Actuator（已在配置中启用），可以动态修改日志级别：

```bash
# 查看当前日志级别
curl http://localhost:8080/actuator/loggers/com.example.cloudnotes

# 动态修改为 DEBUG
curl -X POST http://localhost:8080/actuator/loggers/com.example.cloudnotes \
  -H "Content-Type: application/json" \
  -d '{"configuredLevel": "DEBUG"}'
```

## 📌 注意事项

1. **日志文件路径**：默认在项目根目录的 `logs/` 文件夹
2. **日志级别**：生产环境建议使用 WARN 或 INFO
3. **性能影响**：日志已配置异步写入，对性能影响很小
4. **日志清理**：系统会自动清理超过 30 天的日志
5. **敏感信息**：确保不要记录密码、token 等敏感数据
