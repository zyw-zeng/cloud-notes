## ✅ 当前方案：Caffeine 本地缓存

### 优点
- ✅ 无需外部依赖（Redis、Memcached等）
- ✅ 配置简单，开箱即用
- ✅ 性能极高（内存访问）
- ✅ 适合单机部署

### 缓存配置

**自动过期策略**：
- **写入后**：30分钟自动过期
- **访问后**：10分钟无访问自动过期
- **最大条目**：1000条

**缓存名称**：
1. `notifications` - 通知缓存
2. `notificationCount` - 未读数量缓存
3. `userNotifications` - 用户通知列表缓存

## 🔄 缓存策略

### 1. 查询操作（使用缓存）

```java
@Cacheable(value = "userNotifications", key = "#username + '_unread'")
public List<Notification> getUnreadNotifications(String username) {
    // 首次查询数据库，结果存入缓存
    // 再次查询直接返回缓存
}
```

**缓存Key规则**：
- 未读通知：`username_unread`
- 最近通知：`username_recent_10`
- 未读数量：`username`

---

### 2. 修改操作（清除缓存）

```java
@CacheEvict(value = "userNotifications", key = "#username + '_unread'")
public void markAsRead(Long id, String username) {
    // 修改数据库后，自动清除相关缓存
    // 下次查询会重新加载最新数据
}
```

**自动清除时机**：
- ✅ 创建新通知
- ✅ 标记通知为已读
- ✅ 标记所有为已读
- ✅ 清理旧通知

## 🚀 升级到 Redis（可选）

### 适用场景
- 多服务器部署（集群）
- 需要跨进程共享缓存
- 需要持久化缓存

### 1. 添加 Redis 依赖

在 `pom.xml` 中添加：

```xml
<!-- Redis -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

<!-- 可选：使用Lettuce客户端 -->
<dependency>
    <groupId>io.lettuce.core</groupId>
    <artifactId>lettuce-core</artifactId>
</dependency>
```

### 2. 配置 Redis 连接

在 `application.yml` 中添加：

```yaml
spring:
  redis:
    host: localhost
    port: 6379
    password: your_password  # 如果有密码
    database: 0
    timeout: 3000ms
    lettuce:
      pool:
        max-active: 8
        max-wait: -1ms
        max-idle: 8
        min-idle: 0
  cache:
    type: redis
    redis:
      time-to-live: 1800000  # 30分钟（毫秒）
      cache-null-values: false
```

### 3. 修改 CacheConfig.java

```java
package com.example.cloudnotes.config;

import org.springframework.cache.annotation.EnableCaching;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.cache.RedisCacheConfiguration;
import org.springframework.data.redis.cache.RedisCacheManager;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.serializer.GenericJackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.RedisSerializationContext;

import java.time.Duration;

/**
 * Redis 缓存配置
 */
@Configuration
@EnableCaching
public class CacheConfig {

    public static final String NOTIFICATION_CACHE = "notifications";
    public static final String NOTIFICATION_COUNT_CACHE = "notificationCount";
    public static final String USER_NOTIFICATIONS_CACHE = "userNotifications";

    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory connectionFactory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
                .entryTtl(Duration.ofMinutes(30))  // 30分钟过期
                .serializeValuesWith(
                    RedisSerializationContext.SerializationPair.fromSerializer(
                        new GenericJackson2JsonRedisSerializer()
                    )
                );

        return RedisCacheManager.builder(connectionFactory)
                .cacheDefaults(config)
                .build();
    }
}
```

### 4. 启动 Redis 服务器

```bash
# Docker 方式
docker run -d --name redis -p 6379:6379 redis:latest

# 或使用本地安装的 Redis
redis-server
```

### 5. 验证 Redis 缓存

```bash
# 连接 Redis
redis-cli

# 查看所有key
127.0.0.1:6379> KEYS *

# 查看缓存内容
127.0.0.1:6379> GET userNotifications::testuser_unread
```

## 🔍 性能对比

### Caffeine vs Redis

| 特性 | Caffeine | Redis |
|------|----------|-------|
| 读取速度 | 极快（纳秒级）| 快（毫秒级）|
| 部署方式 | 单机 | 支持集群 |
| 持久化 | 不支持 | 支持 |
| 跨进程共享 | 不支持 | 支持 |
| 内存占用 | 应用内存 | 独立进程 |
| 运维成本 | 低 | 中 |

### 建议

- **开发环境**：使用 Caffeine（当前方案）
- **小型应用**：使用 Caffeine
- **生产环境（单机）**：使用 Caffeine
- **生产环境（集群）**：使用 Redis
- **高并发场景**：使用 Redis + Caffeine 二级缓存

## 📋 缓存API

### 手动清除缓存（如需要）

```java
@Autowired
private CacheManager cacheManager;

// 清除指定用户的缓存
public void clearUserCache(String username) {
    Cache cache = cacheManager.getCache(CacheConfig.USER_NOTIFICATIONS_CACHE);
    if (cache != null) {
        cache.evict(username + "_unread");
        cache.evict(username + "_recent_10");
    }
}

// 清除所有缓存
public void clearAllCache() {
    cacheManager.getCacheNames().forEach(cacheName -> {
        Cache cache = cacheManager.getCache(cacheName);
        if (cache != null) {
            cache.clear();
        }
    });
}
```

## ⚙️ 缓存配置调优

### 调整过期时间

在 `CacheConfig.java` 中修改：

```java
cacheManager.setCaffeine(Caffeine.newBuilder()
    .maximumSize(1000)                          // 最大1000条
    .expireAfterWrite(30, TimeUnit.MINUTES)     // 写入后30分钟过期
    .expireAfterAccess(10, TimeUnit.MINUTES)    // 访问后10分钟过期
    .recordStats());
```

### 根据业务调整

| 场景 | 建议配置 |
|------|---------|
| 高频查询 | 增加 `maximumSize` 和过期时间 |
| 内存紧张 | 减少 `maximumSize` 和过期时间 |
| 实时性要求高 | 减少过期时间，或不使用缓存 |

## 🎯 最佳实践

### 1. 什么应该缓存？
✅ 频繁查询的数据（未读数量）  
✅ 变化不频繁的数据（用户通知列表）  
✅ 计算成本高的数据  

❌ 实时性要求极高的数据  
❌ 大对象（>1MB）  
❌ 敏感信息（密码、Token）

### 2. 缓存Key设计

**好的设计**：
```
userNotifications::testuser_unread
userNotifications::testuser_recent_10
notificationCount::testuser
```

**不好的设计**：
```
notifications_all
user_data
cache_1
```

### 3. 缓存一致性

- ✅ 修改数据时立即清除缓存
- ✅ 使用事务保证原子性
- ✅ 设置合理的过期时间
- ❌ 不要无限期缓存

## 🔧 故障排查

### Q1: 缓存没有生效？

**检查清单**：
1. ✅ `@EnableCaching` 注解存在
2. ✅ `@Cacheable` 注解参数正确
3. ✅ 方法是 public
4. ✅ 不是在同一类内部调用（需通过代理）

### Q2: 数据不一致？

**原因**：修改数据时没有清除缓存

**解决**：确保使用 `@CacheEvict` 注解

### Q3: 内存占用过高？

**解决**：
1. 减少 `maximumSize`
2. 减少过期时间
3. 不缓存大对象

## 📊 监控与统计

### Caffeine 统计信息

```java
@RestController
@RequestMapping("/api/admin/cache")
public class CacheAdminController {
    
    @Autowired
    private CacheManager cacheManager;
    
    @GetMapping("/stats")
    public Map<String, Object> getCacheStats() {
        Map<String, Object> stats = new HashMap<>();
        
        cacheManager.getCacheNames().forEach(cacheName -> {
            Cache cache = cacheManager.getCache(cacheName);
            if (cache instanceof CaffeineCache) {
                com.github.benmanes.caffeine.cache.Cache<Object, Object> nativeCache = 
                    (com.github.benmanes.caffeine.cache.Cache<Object, Object>) 
                    ((CaffeineCache) cache).getNativeCache();
                
                CacheStats cacheStats = nativeCache.stats();
                stats.put(cacheName, Map.of(
                    "hitCount", cacheStats.hitCount(),
                    "missCount", cacheStats.missCount(),
                    "hitRate", cacheStats.hitRate(),
                    "size", nativeCache.estimatedSize()
                ));
            }
        });
        
        return stats;
    }
}
```
