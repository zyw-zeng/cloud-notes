## 为什么使用环境变量

### ❌ 之前的问题（硬编码）

```yaml
# ⚠️ 危险：敏感信息直接写在配置文件中
datasource:
  username: root
  password: admin123

jwt:
  secret: your-256-bit-secret-key
```

**存在的风险：**
1. ❌ **安全风险** - 密码明文存储在代码仓库中
2. ❌ **泄露风险** - 代码提交到 Git 后，密码永久保存在历史记录中
3. ❌ **环境混乱** - 开发、测试、生产环境使用相同的密码
4. ❌ **难以管理** - 修改密码需要修改代码并重新部署

### ✅ 使用环境变量的优势

```yaml
# ✅ 安全：从环境变量读取
datasource:
  username: ${DB_USERNAME:root}
  password: ${DB_PASSWORD:admin123}

jwt:
  secret: ${JWT_SECRET:dev-key}
```

**带来的好处：**
1. ✅ **安全** - 敏感信息不进入代码仓库
2. ✅ **灵活** - 不同环境使用不同的配置
3. ✅ **易管理** - 修改配置无需重新部署代码
4. ✅ **符合规范** - 遵循 12-Factor App 原则

## 环境变量列表

### 必需的环境变量

| 变量名 | 说明 | 默认值 | 生产环境必填 |
|--------|------|--------|--------------|
| `DB_USERNAME` | 数据库用户名 | `root` | ✅ 是 |
| `DB_PASSWORD` | 数据库密码 | `admin123` | ✅ 是 |
| `JWT_SECRET` | JWT 签名密钥 | `dev-secret-key...` | ✅ 是 |

### 可选的环境变量

| 变量名 | 说明 | 默认值 | 备注 |
|--------|------|--------|------|
| `REDIS_PASSWORD` | Redis 密码 | 空 | Redis 未设置密码时可不配置 |
| `DB_HOST` | 数据库主机地址 | `localhost` | 可在 URL 中配置 |
| `DB_PORT` | 数据库端口 | `3306` | 可在 URL 中配置 |
| `REDIS_HOST` | Redis 主机地址 | `localhost` | - |
| `REDIS_PORT` | Redis 端口 | `6379` | - |

## 配置方法

### 方式一：操作系统环境变量（推荐生产环境）

#### Windows (PowerShell)

**临时设置（当前会话有效）：**
```powershell
$env:DB_USERNAME="cloud_notes_user"
$env:DB_PASSWORD="your_secure_password"
$env:JWT_SECRET="your_jwt_secret_key_min_256_bits"
$env:REDIS_PASSWORD="your_redis_password"
```

**永久设置（系统级）：**
```powershell
# 设置用户级环境变量
[System.Environment]::SetEnvironmentVariable("DB_USERNAME", "cloud_notes_user", "User")
[System.Environment]::SetEnvironmentVariable("DB_PASSWORD", "your_secure_password", "User")
[System.Environment]::SetEnvironmentVariable("JWT_SECRET", "your_jwt_secret_key", "User")

# 或使用系统设置
# 控制面板 -> 系统 -> 高级系统设置 -> 环境变量
```

#### Linux / macOS (Bash/Zsh)

**临时设置（当前会话有效）：**
```bash
export DB_USERNAME="cloud_notes_user"
export DB_PASSWORD="your_secure_password"
export JWT_SECRET="your_jwt_secret_key_min_256_bits"
export REDIS_PASSWORD="your_redis_password"
```

**永久设置（添加到配置文件）：**
```bash
# 编辑 ~/.bashrc 或 ~/.zshrc
nano ~/.bashrc

# 添加以下内容
export DB_USERNAME="cloud_notes_user"
export DB_PASSWORD="your_secure_password"
export JWT_SECRET="your_jwt_secret_key_min_256_bits"
export REDIS_PASSWORD="your_redis_password"

# 重新加载配置
source ~/.bashrc
```

### 方式二：IDE 配置（推荐开发环境）

#### IntelliJ IDEA

1. 打开 `Run/Debug Configurations`
2. 选择你的 Spring Boot 应用
3. 找到 `Environment variables` 字段
4. 添加环境变量：
   ```
   DB_USERNAME=root;DB_PASSWORD=admin123;JWT_SECRET=dev-secret-key
   ```

#### VS Code

创建 `.vscode/launch.json`：
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "name": "Spring Boot App",
      "request": "launch",
      "mainClass": "com.example.cloudnotes.CloudNotesApplication",
      "env": {
        "DB_USERNAME": "root",
        "DB_PASSWORD": "admin123",
        "JWT_SECRET": "dev-secret-key-for-local-development-only"
      }
    }
  ]
}
```

### 方式三：.env 文件（开发环境）

⚠️ **注意：.env 文件必须添加到 .gitignore，不能提交到 Git！**

#### 1. 创建 .env 文件

在项目根目录创建 `.env` 文件：
```bash
# 数据库配置
DB_USERNAME=root
DB_PASSWORD=admin123

# JWT 配置
JWT_SECRET=dev-secret-key-for-local-development-only-change-in-production

# Redis 配置（可选）
REDIS_PASSWORD=
```

#### 2. 添加到 .gitignore

```bash
# 确保 .env 文件不被提交
echo ".env" >> .gitignore
```

#### 3. 创建 .env.example 模板

创建 `.env.example` 作为示例（可以提交到 Git）：
```bash
# 数据库配置
DB_USERNAME=your_db_username
DB_PASSWORD=your_db_password

# JWT 配置
JWT_SECRET=your_jwt_secret_key_min_256_bits

# Redis 配置（可选）
REDIS_PASSWORD=your_redis_password
```

#### 4. 使用 Spring Boot 加载 .env

添加依赖（可选，Spring Boot 默认不支持 .env）：
```xml
<dependency>
    <groupId>me.paulschwarz</groupId>
    <artifactId>spring-dotenv</artifactId>
    <version>4.0.0</version>
</dependency>
```

### 方式四：Docker 环境变量

#### docker-compose.yml

```yaml
version: '3.8'
services:
  app:
    image: cloud-notes:latest
    environment:
      - DB_USERNAME=cloud_notes_user
      - DB_PASSWORD=${DB_PASSWORD}  # 从宿主机环境变量读取
      - JWT_SECRET=${JWT_SECRET}
      - REDIS_PASSWORD=${REDIS_PASSWORD}
    env_file:
      - .env  # 或从文件读取
```

#### Dockerfile

```dockerfile
FROM openjdk:21-jdk-slim
WORKDIR /app
COPY target/cloud-notes.jar app.jar

# 环境变量可以在运行时传入
ENV DB_USERNAME=root
ENV DB_PASSWORD=admin123

ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 方式五：Kubernetes ConfigMap/Secret

#### ConfigMap（非敏感配置）

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: cloud-notes-config
data:
  DB_HOST: "mysql-service"
  DB_PORT: "3306"
  REDIS_HOST: "redis-service"
```

#### Secret（敏感配置）

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: cloud-notes-secret
type: Opaque
data:
  DB_USERNAME: Y2xvdWRfbm90ZXNfdXNlcg==  # base64 编码
  DB_PASSWORD: eW91cl9zZWN1cmVfcGFzc3dvcmQ=
  JWT_SECRET: eW91cl9qd3Rfc2VjcmV0X2tleQ==
```

#### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cloud-notes
spec:
  template:
    spec:
      containers:
      - name: app
        image: cloud-notes:latest
        envFrom:
        - configMapRef:
            name: cloud-notes-config
        - secretRef:
            name: cloud-notes-secret
```

## 生成安全密钥

### JWT 密钥生成

#### 方法一：使用 OpenSSL（推荐）

```bash
# 生成 256 位（32 字节）Base64 编码的密钥
openssl rand -base64 32

# 生成 512 位（64 字节）Base64 编码的密钥（更安全）
openssl rand -base64 64
```

**示例输出：**
```
K7gNU3sdo+OL0wNhqoVWhr3g6s1xYv72ol/pe/Unols=
```

#### 方法二：使用 Java 代码

```java
import java.security.SecureRandom;
import java.util.Base64;

public class KeyGenerator {
    public static void main(String[] args) {
        SecureRandom random = new SecureRandom();
        byte[] key = new byte[64]; // 512 位
        random.nextBytes(key);
        String encodedKey = Base64.getEncoder().encodeToString(key);
        System.out.println("JWT_SECRET=" + encodedKey);
    }
}
```

#### 方法三：在线生成器

访问：https://www.allkeysgenerator.com/Random/Security-Encryption-Key-Generator.aspx
- 选择 256-bit 或 512-bit
- 选择 Base64 编码
- 点击生成

### 数据库密码生成

```bash
# 生成强随机密码
openssl rand -base64 24
```

```bash
# 环境变量
DB_USERNAME=test_user

REDIS_PASSWORD=test_redis_password
```

- 使用独立的测试数据库

### 生产环境

```bash
# ⚠️ 生产环境必须使用强密钥！
DB_USERNAME=prod_cloud_notes_user
DB_PASSWORD=Pr0d_S3cur3_P@ssw0rd_2024!#$
JWT_SECRET=K7gNU3sdo+OL0wNhqoVWhr3g6s1xYv72ol/pe/Unols=
```

- ✅ JWT 密钥使用 OpenSSL 生成的 256 位以上密钥
- ✅ 定期轮换密钥
- ✅ 使用密钥管理服务（如 AWS Secrets Manager、Azure Key Vault）

## 常见问题

### Q1: 如何验证环境变量是否生效？

**方法一：在代码中打印（仅开发环境）**
```java
@Value("${DB_USERNAME}")
private String dbUsername;

@PostConstruct
public void init() {
    System.out.println("DB_USERNAME: " + dbUsername);
}
```

**方法二：使用 Actuator**
```bash
# 访问配置端点（需要启用 Actuator）
curl http://localhost:8080/actuator/env
```

**方法三：启动日志查看**
```bash
# 启动应用时查看日志，确认配置加载
mvn spring-boot:run
```

---

### Q2: 环境变量未生效，还是使用默认值？

**可能原因：**
1. 环境变量名称拼写错误
2. IDE 未重启，环境变量未加载
3. 操作系统环境变量未生效（需要重启终端）

**解决方法：**
```bash
# 检查环境变量是否存在
# Windows
echo $env:DB_USERNAME

# Linux/macOS
echo $DB_USERNAME

# 如果为空，说明未设置成功
```

---

### Q3: 如何在不同环境使用不同配置？

**使用 Spring Profile：**

```bash
# 开发环境
java -jar app.jar --spring.profiles.active=dev

# 生产环境
java -jar app.jar --spring.profiles.active=prod
```

配置文件会自动加载：
- `application.yml` - 通用配置
- `application-dev.yml` - 开发环境配置
- `application-prod.yml` - 生产环境配置

---

### Q4: JWT 密钥需要多长？

**推荐长度：**
- ✅ **最低要求**：256 位（32 字节）
- ✅ **推荐长度**：512 位（64 字节）
- ❌ **不安全**：少于 256 位

**验证密钥长度：**
```bash
# Base64 编码的密钥，长度应该 >= 44 个字符（256 位）
echo "K7gNU3sdo+OL0wNhqoVWhr3g6s1xYv72ol/pe/Unols=" | wc -c
```

---

### Q5: 如何安全地分享配置给团队成员？

**❌ 不要：**
- 不要通过邮件发送密码
- 不要在聊天工具中发送
- 不要提交到 Git

**✅ 推荐：**
1. 使用密码管理工具（如 1Password、LastPass）
2. 使用公司内部的密钥管理系统
3. 面对面或加密通道传递
4. 提供 `.env.example` 模板，让成员自己配置

---

### Q6: 生产环境密钥泄露了怎么办？

**立即行动：**
1. ✅ 立即更换所有密钥
2. ✅ 重启应用使新密钥生效
3. ✅ 检查日志，确认是否有异常访问
4. ✅ 通知团队成员
5. ✅ 审查代码仓库，确保密钥未提交

**预防措施：**
- 定期轮换密钥（建议每 3-6 个月）
- 使用密钥管理服务
- 启用访问日志和审计
- 限制密钥访问权限

## 最佳实践总结

### ✅ 必须做的

1. ✅ **生产环境必须使用环境变量**，禁止硬编码
2. ✅ **JWT 密钥必须使用强随机密钥**（256 位以上）
3. ✅ **将 .env 文件添加到 .gitignore**
4. ✅ **提供 .env.example 模板**供团队参考
5. ✅ **定期轮换生产环境密钥**

### ❌ 禁止做的

1. ❌ **禁止将密码提交到 Git**
2. ❌ **禁止在代码中硬编码密码**
3. ❌ **禁止使用弱密码**（如 123456、admin）
4. ❌ **禁止在日志中打印密码**
5. ❌ **禁止通过不安全的方式分享密码**
